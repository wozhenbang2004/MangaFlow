# 漫流 · MangaFlow

Current 2026-11-12 interface: an ordinary flat full-cover collection grid, without 3D shelves or follow/hoard/pause groups; picture/spread hearts and image collection (replacing bookmark/notes controls); a reading-edge clock outside the console and actual foreground reading statistics; task-grouped settings, full-segment selections and shared paper-color previews; compact heat/native-score bands with real remaining-source counts; a floating glass discovery/ranking header over the original scrolling content; softer ranking transitions; finger-driven pull and curved swipe removal; glass search that hides underlying history chrome during its full presence; a matching glass downloads header with summary/import/queue/filter actions over the retained lists; immediate short cold-start reveal; local image/silent-video wallpaper; user-selected comic-window icon B. Settings → 外观 → 壁纸 imports ordinary image/video files. Wallpaper Engine scene/project/mobile packages are not generic videos. Build and device behavior remain pending the main CI/user feedback path.

一个专注于阅读的 Android 漫画客户端。使用 Kotlin 和 Jetpack Compose，支持 Android 8.0 及以上。

[项目主页](https://github.com/wozhenbang2004/MangaFlow)

## 功能

- 漫画推荐、日／周／月／总热榜、最近更新、搜索、大图详情与连续加载的紧凑章节目录，公开阅读通过拷贝漫画匿名来源获取。
- 纵向滚动、从左至右和从右至左翻页，图片缩放，阅读底色、亮屏和页间留白设置。
- 本地书架、每章独立的阅读进度和长图位置，从历史记录直接继续阅读，目录在后台加载。
- 相邻图片预加载、短期章节缓存和临近章末的下一章准备，图片沿用已有磁盘缓存。
- 应用内账号密码登录、个人 Cookie / Token 导入，云端收藏、云端章节记录和收藏同步；登录页可截图，报错可复制。
- 章节下载、暂停与继续、失败重试、离线阅读；后台任务由 WorkManager 管理。
- 推荐、热榜、搜索、书架、历史和详情共用紧凑评分／热度徽标，保留各站原生量表、评分人数和贝叶斯评分名称；榜期热度、总热度与评分分别显示，没有可靠匹配时不编造数值。
- 详情评论融合拷贝、Bangumi、AniList、MangaUpdates、MyAnimeList（经 Tenrai）、Kitsu 与 Shikimori 的已确认作品内容；MangaDex、腾讯动漫、巴哈姆特和漫画柜补充评分，MangaBaka 辅助作品别名与跨站编号关联。真实头像、剧透折叠、各源分页与失败重试沿用同一紧凑界面，不增加来源管理抽屉。
- 每章末尾和阅读工具栏打开同一份本话评论，只接受拷贝当前章节 UUID 与可严格映射的 Dantotsu 章评，支持后者的本话回复。整部作品评论始终留在漫画详情，评论不计入漫画页数。
- 推荐、榜单与搜索持久缓存，按条件保留列表和滚动位置；设置中分别管理浏览、评分／评论和图片缓存。
- 应用内检查更新、更新提醒、安装包断点续传与覆盖安装。
- 侧栏“找漫画”接入 MangaBaka 的上升中、冷门佳作与公开主题书单；详情右上角的相似／系列图标可查看相似作品、前传续作和同作者作品。资料条目通过“在拷贝中查找”取得实际阅读版本，由用户选择后进入原有章节页。

第三方来源的错误、限流和条目未匹配保留真实状态；评论正文不再展示逐站提示，手动匹配与重试可从筛选里的“来源设置”按需展开。不使用示例漫画或虚构评论填充。

## 推荐、热榜与讨论

发现页的推荐使用拷贝公开推荐列表，顶部可左右滑动浏览六项完整宽度的推荐并显示位置提示；每六秒轻量切换，按住、拖动、离屏或应用退到后台时暂停，读屏触摸探索时不自动切换。下方推荐、最近更新和搜索结果采用三列封面。右上角的最近阅读打开紧凑列表，点击直接回到保存的章节与页内位置；搜索平时只显示图标，点击后悬浮展开输入与结果面板，关闭后回到原列表。热榜可切换日、周、月、总榜与男频／女频，保持来源的排序。日榜表示上升最快，列表数字统一标作热度，不将它解释为该时间段的阅读人数。最近更新按来源更新时间排列。当前没有将来源推荐包装成个人化推荐。

详情页使用固定大图和随手势移动的前景信息，简介放在书名旁的玻璃面板里；从信息面板上纵向拖动也能展开或收起大图。下方保留“章节／评论”两个分区，章节网格连续加载，分组与下载操作直接放在工具栏。下载模式只切换每章的固定图标位置；底部阅读按钮显示实际章节名。

漫画详情和阅读器共用紧凑评论行，昵称、来源徽标和简短日期放在正文上方；多源评论按时间混排，向下滑动继续加载。拷贝评论中的 `count` 表示回复数，展开时读取对应作品评论的回复。一站失败不会把其他站的内容抹掉，来源处理按需放在筛选内。阅读时的时间和页码使用右下角淡字，随独立阅读底色调整，不再加底板或边框。具体设计取舍与成熟组件来源见 [DESIGN.md](DESIGN.md)。

内容扩展的具体接口与优先顺序见 [内容与功能接口研究](research/content-api-expansion-20261112.md)。MangaBaka 的相似推荐、上升／冷门作品、系列／作者关系与主题书单已完成代码接入；多语言正文、私人漫画库、外部追漫同步和漫画翻译仍为后续方向。实际服务与手机效果待 CI 产物和用户反馈确认。

本话讨论始终绑定当前章节 UUID。Dantotsu 另外要求确认 AniList 漫画 ID 和唯一的整数主线章号，并核对返回评论及回复的作品、章号和父评论；不以目录序号猜章号，不映射番外、小数章、合并话或上／下篇。章末浮动预览与工具栏评论共享请求和分页状态，滑到章末不会插入长评论列表。长评正文默认按可能剧透折叠，用户可以主动展开；Kitsu 的当前短评没有剧透字段，保守折叠并说明。来源没有明确剧透标记的其他普通评论不保证没有剧透。

作品匹配只接受漫画类型、明确跨站 ID 或唯一且作者不冲突的标题匹配；歧义条目保留选择与持久关联。MangaUpdates 的长 ID、MangaDex 的 UUID 都按字符串保存。详情新增来源并发最多三个；列表评分按来源独立限制并发，保留 host 请求间隔和真实 Retry-After。每站失败、未匹配和空内容保持区分。MangaUpdates 两路评论中一路失败时保留另一条路的正文，重试当前页并按真实 ID 去重。点赞、踩、回复数与“有用”各自保留上游含义。

详情页和热榜行展示全部已有评分；紧凑封面徽标最多展示两个分数，再以 `+N 评分` 提示更多。推荐、榜单、搜索、书架和历史中的可见漫画自动获取全部九家评分源的身份与分数，不读取评论页，也不要求先打开详情。已知量表直接显示 `/5`、`/10` 或 `/100`，未知满分保留原始分值。已有缓存先显示，各来源独立补齐；刷新榜单同时重试可见漫画的评分，清理评分缓存后重新启动仍可见的条目。失败仅影响当前漫画和来源，保留旧成功评分；未确认对应作品或来源没有评分时不制造数字。

MangaBaka 在详情的附加来源之前解析：优先用已确认的 AniList／MAL／Kitsu／MangaUpdates 编号反查，最多两条线索；没有记录时再比较标题和作者。相互冲突、合并、删除或多个对应条目不会自动取第一项；每个原站再次核验作品身份。列表并发评分只共享各原站已确认的身份，不直接传播 MangaBaka 映射。手工确认后恢复尚未完成的来源；清缓存或更改关联会废弃旧回执。只提供评分／资料的来源重试资料接口，不请求评论分页，也不把缺失评论标成零条。

腾讯和巴哈使用已有公开 HTML 解析证据；漫画柜使用公开源码中的检索、详情及只读评分协议。腾讯详情样本来自 2021 年，巴哈元数据选择器有历史源码依据，当前 DOM 与匿名访问均未实测。出现结构变化、限流或拒绝访问时显示失败；没有替代身份、登录态或绕过通道。腾讯满分未知时只显示原始分值；漫画柜分数按真实投票桶计算，不冒称来源的贝叶斯分或跨站综合分。

## 缓存与返回体验

推荐、最近更新、搜索和各日／周／月／总榜分别保存完整列表快照。切换回来先恢复已有内容；重启后可从磁盘恢复。单页数据到期后在原内容上方用细线提示后台刷新，失败时保留已有漫画；已经翻过多页的列表保持原快照，避免返回后突然跳到顶部或混入新旧排序。主动刷新重新获取第一页。首次没有缓存仍需要等待来源响应。

推荐／更新／搜索缓存有效期为15分钟，日／周榜30分钟，月／总榜1小时；磁盘上限8 MiB、最多24个条件，过旧快照最多保留7天。评分资料有效期6小时，最多256本、512 KiB；只对当前显示的漫画取得评分，不为徽标请求整页评论。每个来源独立保存成功结果，暂时失败不会抹掉已有数值。离屏时停止无用的元数据请求。

拷贝作品／回复／章评短期保留3分钟；各作品评价来源独立缓存首屏，单站失败不影响其他来源，清理时也清除新增来源的分页和章节身份缓存。图片与头像共用Coil内存和256 MiB磁盘缓存。**设置 → 缓存**可以分别清理推荐与热榜、评分与评论、图片与头像；书架、阅读进度、手动漫画关联和下载章节独立保存。

MangaBaka 发现资料使用独立的4 MiB HTTP缓存并遵守服务端缓存规则，刷新会重新验证；其大小和清理包含在评分／资料缓存中，封面缩略图仍使用原有图片缓存。返回与切换保留当前真实列表及位置，失败保留已有候选并可重试。公开发现不需要账号，Mix 多种子推荐、资讯和外部账号同步没有作为本批功能加入。

## 账号与匿名阅读

从侧栏的 **账号与云端**，或书架右上角的 **云端书架** 进入登录页面，直接填写用户名和密码。账号密码登录沿用 Relay 桌面端的 Web 表单和个人资料 API 配对，账号客户端使用 HTTP/1.1；资料验证成功后才保存个人 Token 和 `WEB_API` 凭据通道。固定登录地址与后续个人接口分开，无需打开网页登录页面。旧 App／Web 登录态保留原有验证通道。

需要手动导入网页凭据时，点击 **导入 Cookie / Token**，粘贴自己的完整 Cookie、`token=…`、`Token …`、`Authorization: Token …` 或单独的 Token。手动导入及旧版已保存的网页凭据继续使用原有网页资料验证，不会在升级后被当成 App 凭据。密码与 Token 默认遮挡，只在页面内存中停留，提交后清空；用户名保留，方便纠正输入。登录页允许截图，错误支持选中文字和 **复制错误**，复制内容包含应用版本，不包含提交的密码或 Token。来源返回 210 时保留其具体提示，不把所有 210 都解释成账号受限；来源要求等待时仍遵守重试时间。登录提交和账号资料验证分别显示失败原因，不自动向其他接口重复提交密码。

当前请求对照 Relay-Desktop 固定提交 `0079af7ca2242b51f14d9c3cf1874b12c18888e8` 的 `CopyMangaProtocol.cs`、`CopyMangaService.WebLogin.cs`、`CopyMangaService.Account.cs` 及 HttpClient 构造。此前 App 账号链的 CopyManga Neo／Venera 参考仍用于旧版 App 登录态，不能据此把新 Web 凭据改走 App 通道。

**验证状态：** 用户最新反馈 Relay 桌面端可以登录，手机仍报 210。历史 App 登录排查在云端收到过相同 210，随后停止。本轮只对照源码并修正传输兼容，没有运行登录／接口测试，也没有个人账号成功回执。请求字段与 HTTP 版本一致不证明服务端、出口网络或 TLS 环境一致；手机登录结果仍待反馈。

公开搜索、详情、目录、正文、图片和下载使用独立匿名客户端。目录和正文使用拷贝的匿名 App 接口，目录按分组完整分页读取，正文按来源返回的页序排列。匿名标识在设备上随机生成并保存，不读取硬件身份，不因来源错误而更换；个人 Token 只用于固定的个人资料、收藏和云端章节记录接口。图片请求不携带 App 签名、匿名标识或个人凭据。

登录后可分页浏览云端收藏和阅读记录。在详情页变更本地收藏时会同步这次操作；同步失败保留本地结果，并在账号页提供重试。云端书架中的移除操作仅修改云端收藏。正文图片已出现在阅读视口后，才异步同步当前章节，账号接口失败不会阻塞阅读。

云端记录精确到章节，本机保存页码、滚动偏移和长图内部位置。退出账号会清空当前账号和云端列表，保留本地书架、阅读进度与已下载章节。

历史记录直接打开上次阅读的章节和位置；已下载章节优先离线读取。完整目录在后台补齐，失败时可在阅读器目录中重试。相邻页预读只准备小范围图片，临近章末才准备下一章，离开阅读器时取消无用请求。首次阅读和网络较慢时仍可能需要等待图片下载。

重新打开或刷新详情时，已有可用目录会继续显示；刷新失败保留旧目录和已下载章节，并显示具体原因。有本地阅读记录时，详情页的“继续阅读”直接进入上次章节，不以重新获取目录为前提。只有完整、归属一致的目录和正文才写入短期缓存，空响应不会覆盖成功结果。

匿名协议的端点、请求字段与页序依据 CopyManga Neo 的固定版本（`https://github.com/rchdliang/CopyManga_Neo/tree/36ec484fb6ee166456f8025917963fcf8e9e2ce8`） 和 Venera 的公开来源配置（`https://github.com/venera-app/venera-configs/blob/a04e05591f7832f7166d6660546613c114d6738a/copy_manga.js`） 核对，并通过真实匿名目录、正文和图片请求确认；未复制其客户端实现。来源明确拒绝或要求等待时保留错误，不自动轮换域名、身份或账号。

## 自动发布

推送到 `main` 或手动启动 **Android release** 后，流水线会：

1. 为本次运行分配 `0.1.<run_number>`，`versionCode` 为 `10000 + run_number`。
2. 编译 release APK，并使用同一份 PKCS12 密钥签名。
3. 生成签名更新清单 `latest.json` 和 `SHA256SUMS`。
4. 上传完整资产后发布 GitHub Release，供用户直接下载和应用匿名检查更新。

已发布的同一次运行重跑会保留原资产。发布前后核对源提交与 tag；旧构建不会覆盖新的 `main` 版本。

仓库 Actions Secrets 使用 `MANGAFLOW_SIGNING_KEYSTORE_B64` 与 `MANGAFLOW_SIGNING_PASSWORD`。首次建立签名身份时，可运行 `scripts/create-signing-key.py`，参数为仓库外的私密目录。密钥 alias 为 `mangaflow`；发布后需要持续保留同一密钥及密码。

客户端使用当前安装包的签名证书验证更新清单，再核对 APK 大小、SHA256、包名、版本和签名，最后由 Android 系统确认安装。自动检查周期为六小时，具体调度受系统后台策略影响。
