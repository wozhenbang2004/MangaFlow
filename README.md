# 漫流 · MangaFlow

一个专注于阅读的 Android 漫画客户端。使用 Kotlin 和 Jetpack Compose，支持 Android 8.0 及以上。

[下载最新版本](https://github.com/wozhenbang2004/MangaFlow/releases/latest) · [构建与发布](https://github.com/wozhenbang2004/MangaFlow/actions/workflows/android-release.yml)

## 功能

- 漫画推荐、日／周／月／总热榜、最近更新、搜索、紧凑详情与分页章节目录，公开阅读通过拷贝漫画匿名来源获取。
- 纵向滚动、从左至右和从右至左翻页，图片缩放，阅读底色、亮屏和页间留白设置。
- 本地书架、每章独立的阅读进度和长图位置，从历史记录直接继续阅读，目录在后台加载。
- 相邻图片预加载、短期章节缓存和临近章末的下一章准备，图片沿用已有磁盘缓存。
- 应用内账号密码登录、个人 Cookie / Token 导入，云端收藏、云端章节记录和收藏同步；登录页可截图，报错可复制。
- 章节下载、暂停与继续、失败重试、离线阅读；后台任务由 WorkManager 管理。
- 推荐、热榜、搜索、书架、历史和详情共用紧凑评分／热度徽标，区分拷贝榜期热度与总热度、Bangumi 十分制、AniList 百分制；没有可靠匹配时不编造数值。
- 拷贝作品评论与回复、Bangumi 中文短评、AniList 长评正文分页阅读，显示真实头像及失败占位，评论与作者不再跳转外部网页；多义条目先区分漫画与小说，再按作者和别名匹配，无法唯一确认时可选择并记住关联。
- 每章末尾显示拷贝本章讨论，竖向阅读和左右翻页均可进入；评论不计入漫画页数，续读仍定位到正文。
- 推荐、榜单与搜索持久缓存，按条件保留列表和滚动位置；设置中分别管理浏览、评分／评论和图片缓存。
- 应用内检查更新、更新提醒、安装包断点续传与覆盖安装。

第三方来源的错误、限流和条目未匹配会直接显示，不使用示例漫画或虚构评论填充。

## 推荐、热榜与讨论

发现页的推荐使用拷贝公开推荐列表，顶部可左右滑动浏览六项推荐，露出下一张并显示位置提示；每六秒轻量切换，按住、拖动、离屏或应用退到后台时暂停，读屏触摸探索时不自动切换。下方推荐、最近更新和搜索结果采用三列封面。右上角的最近阅读打开紧凑列表，点击直接回到保存的章节与页内位置；搜索平时只显示图标，点击后展开输入框，关闭后回到原列表。热榜可切换日、周、月、总榜与男频／女频，保持来源的排序。日榜表示上升最快，列表数字统一标作热度，不将它解释为该时间段的阅读人数。最近更新按来源更新时间排列。当前没有将来源推荐包装成个人化推荐。

详情页固定展示紧凑书籍信息与评分热度，下方以“章节／简介／评论”切换。章节默认可见，网格根据可用高度、屏幕宽度和字体大小分页；可点前后箭头或章节范围直接跳页。工具栏提供分组、顺序、搜索、下载模式及上次阅读定位。长按章节可查看完整标题与阅读／下载操作。简介和评论只在各自内容区滚动，返回详情保留分区、筛选和位置；底部阅读按钮参与正常布局，不遮挡正文。

评论分区直接展示完整列表，点击站点切换口碑，不再先看两条预览再打开第二层。拷贝评论中的 `count` 表示回复数，展开时读取对应评论的回复。评分、评论及匹配失败分别显示，一站失败不会把其他站的内容抹掉。具体设计取舍与成熟组件来源见 [DESIGN.md](DESIGN.md)。

章节讨论只使用当前章节 UUID。Bangumi 与 AniList 的作品短评／长评保留在作品详情，不混进本章讨论。长评正文默认按可能剧透折叠，用户可以主动展开；来源没有明确剧透标记的普通评论不保证没有剧透。

## 缓存与返回体验

推荐、最近更新、搜索和各日／周／月／总榜分别保存完整列表快照。切换回来先恢复已有内容；重启后可从磁盘恢复。单页数据到期后在原内容上方用细线提示后台刷新，失败时保留已有漫画；已经翻过多页的列表保持原快照，避免返回后突然跳到顶部或混入新旧排序。主动刷新重新获取第一页。首次没有缓存仍需要等待来源响应。

推荐／更新／搜索缓存有效期为15分钟，日／周榜30分钟，月／总榜1小时；磁盘上限8 MiB、最多24个条件，过旧快照最多保留7天。评分资料有效期6小时，最多256本、512 KiB；只对当前显示的漫画取得评分，不为徽标请求整页评论。每个来源独立保存成功结果，暂时失败不会抹掉已有数值。离屏时停止无用的元数据请求。

拷贝作品／回复／章评短期保留3分钟；Bangumi与AniList分别缓存成功的首屏评价，单站失败不影响另一站。图片与头像共用Coil内存和256 MiB磁盘缓存。**设置 → 缓存**可以分别清理推荐与热榜、评分与评论、图片与头像；书架、阅读进度、手动漫画关联和下载章节独立保存。

## 账号与匿名阅读

从侧栏的 **账号与云端**，或书架右上角的 **云端书架** 进入登录页面，直接填写用户名和密码。账号密码登录使用拷贝 App 协议，登录后通过同一套 App 协议验证账号资料；验证成功后才保存个人 Token 和凭据通道。固定登录地址与后续个人接口分开，使用已持久保存的安装标识，不反复更换设备身份。无需打开网页登录页面。

需要手动导入网页凭据时，点击 **导入 Cookie / Token**，粘贴自己的完整 Cookie、`token=…`、`Token …`、`Authorization: Token …` 或单独的 Token。手动导入及旧版已保存的网页凭据继续使用原有网页资料验证，不会在升级后被当成 App 凭据。密码与 Token 默认遮挡，只在页面内存中停留，提交后清空；用户名保留，方便纠正输入。登录页允许截图，错误支持选中文字和 **复制错误**，复制内容包含应用版本，不包含提交的密码或 Token。来源返回 210 时保留其具体提示，不把所有 210 都解释成账号受限；来源要求等待时仍遵守重试时间。登录提交和账号资料验证分别显示失败原因，不自动向其他接口重复提交密码。

App 账号链的请求字段参照 [CopyManga Neo 的固定版本](https://github.com/rchdliang/CopyManga_Neo/tree/36ec484fb6ee166456f8025917963fcf8e9e2ce8) 和 [Venera 的公开账号协议](https://github.com/venera-app/venera-configs/blob/a04e05591f7832f7166d6660546613c114d6738a/copy_manga.js)，复用已有公开时间戳签名。此改动针对“官方 App 能登录，而原网站登录请求返回 210”的兼容问题；构建、空表单响应及未登录的资料响应均不代表个人登录成功，当前仍需真实账号反馈确认。

**验证状态：** 用户确认官方 App 能登录、官方网页不能登录，并明确要求直接合入 App 协议改动。2026-11-12 用生产 Kotlin 构造的一次真实 App 登录请求，在云端排查环境中以空账号密码也收到相同的 210，随后停止请求。保留这一结果；构建与发布完成不代表个人登录已成功，手机上的实际结果仍待反馈。

公开搜索、详情、目录、正文、图片和下载使用独立匿名客户端。目录和正文使用拷贝的匿名 App 接口，目录按分组完整分页读取，正文按来源返回的页序排列。匿名标识在设备上随机生成并保存，不读取硬件身份，不因来源错误而更换；个人 Token 只用于固定的个人资料、收藏和云端章节记录接口。图片请求不携带 App 签名、匿名标识或个人凭据。

登录后可分页浏览云端收藏和阅读记录。在详情页变更本地收藏时会同步这次操作；同步失败保留本地结果，并在账号页提供重试。云端书架中的移除操作仅修改云端收藏。正文图片已出现在阅读视口后，才异步同步当前章节，账号接口失败不会阻塞阅读。

云端记录精确到章节，本机保存页码、滚动偏移和长图内部位置。退出账号会清空当前账号和云端列表，保留本地书架、阅读进度与已下载章节。

历史记录直接打开上次阅读的章节和位置；已下载章节优先离线读取。完整目录在后台补齐，失败时可在阅读器目录中重试。相邻页预读只准备小范围图片，临近章末才准备下一章，离开阅读器时取消无用请求。首次阅读和网络较慢时仍可能需要等待图片下载。

重新打开或刷新详情时，已有可用目录会继续显示；刷新失败保留旧目录和已下载章节，并显示具体原因。有本地阅读记录时，详情页的“继续阅读”直接进入上次章节，不以重新获取目录为前提。只有完整、归属一致的目录和正文才写入短期缓存，空响应不会覆盖成功结果。

匿名协议的端点、请求字段与页序依据 [CopyManga Neo 的固定版本](https://github.com/rchdliang/CopyManga_Neo/tree/36ec484fb6ee166456f8025917963fcf8e9e2ce8) 和 [Venera 的公开来源配置](https://github.com/venera-app/venera-configs/blob/a04e05591f7832f7166d6660546613c114d6738a/copy_manga.js) 核对，并通过真实匿名目录、正文和图片请求确认；未复制其客户端实现。来源明确拒绝或要求等待时保留错误，不自动轮换域名、身份或账号。

## 构建

环境：JDK 17、Android SDK 35、Build Tools 35.0.0。Gradle 8.9 Wrapper 已包含在仓库中；Android Studio 可直接打开根目录。

```bash
./gradlew :app:assembleDebug
```

调试包位于 `app/build/outputs/apk/debug/app-debug.apk`。正式包由 GitHub Actions 使用固定发布密钥签名；本地调试包的签名不同，不能覆盖正式版。

流水线只负责编译、打包、签名和发布，不运行测试或 lint，不新增自动测试套件。来源接入按授权核对真实 API；构建成功、服务链路验证和 Android 真机体验分别记录，不互相替代。

功能分支的 **Android build** 仅编译调试 APK，供集成前核对编译结果；进入 `main` 后仍走原有固定签名的发布流程。接入新来源前允许用户要求的有界真实匿名 API 读取，不添加自动测试套件。

## 自动发布

推送到 `main` 或手动启动 **Android release** 后，流水线会：

1. 为本次运行分配 `0.1.<run_number>`，`versionCode` 为 `10000 + run_number`。
2. 编译 release APK，并使用同一份 PKCS12 密钥签名。
3. 生成签名更新清单 `latest.json` 和 `SHA256SUMS`。
4. 上传完整资产后发布 GitHub Release，供用户直接下载和应用匿名检查更新。

已发布的同一次运行重跑会保留原资产。发布前后核对源提交与 tag；旧构建不会覆盖新的 `main` 版本。

仓库 Actions Secrets 使用 `MANGAFLOW_SIGNING_KEYSTORE_B64` 与 `MANGAFLOW_SIGNING_PASSWORD`。首次建立签名身份时，可运行 `scripts/create-signing-key.py`，参数为仓库外的私密目录。密钥 alias 为 `mangaflow`；发布后需要持续保留同一密钥及密码。

客户端使用当前安装包的签名证书验证更新清单，再核对 APK 大小、SHA256、包名、版本和签名，最后由 Android 系统确认安装。自动检查周期为六小时，具体调度受系统后台策略影响。

## 代码结构

| 目录 | 职责 |
| --- | --- |
| `data/` | 匿名来源请求、漫画与章节解析、评分和评价匹配 |
| `account/` | 加密账号凭据、个人接口、收藏和云端章节同步 |
| `storage/` | 本地书架、阅读偏好、持久下载队列 |
| `reader/` | 滚动与分页阅读、图片缩放、进度记录 |
| `ui/` | 导航、发现、详情、下载与设置 |
| `update/` | 版本检查、通知、下载校验与安装 |
| `scripts/` | 签名身份创建与发布资产生成 |

Android 源码位于 `app/src/main/java/dev/mangaflow/`。图片加载使用 Coil，缩放使用 Telephoto，玻璃材质使用 Haze。

## 数据与来源

应用不提供自建用户服务或统计 SDK。个人 Token 由 Android Keystore 的 AES/GCM 密钥加密后保存在应用私有空间，密码不保存，退出时删除凭据与对应密钥。账号请求直接访问拷贝漫画的固定个人接口；书架、页内阅读进度、偏好和下载保存在设备上。漫画、评分、评价与应用更新请求直接访问各自来源。仓库不包含漫画文件、个人数据或签名私钥。

漫画和评价内容归其原作者及来源所有，保留作者、来源标记与数据中的出处地址。内容页移除重复外跳入口，评论在应用内阅读。请按来源的使用规则阅读和保存内容。
