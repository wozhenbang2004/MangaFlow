# 成人漫画体验重做 · 2026-11-19

基线：`07bf1b85f96b9de9276fe04278e9499d20603e86`。用户要求按完整审美库系统重做成人漫画全部界面与交互。本次沿现有普通／成人内容身份及独立书架、来源能力、搜索与阅读路径实施；Android 手机／平板与 Windows 是目标端。

主线：从侧栏进入成人分区 → 首屏识别作品和当前来源 → 在作品、作者或标签中找书 → 详情选章／继续阅读 → 回到原筛选和位置。书架把本机收藏、站点收藏与账号操作分清；账号失败保留已有内容并提供对应恢复入口。视觉采用内容主导的连续画布、清晰封面、安静选中态、少量玻璃导航与按需展开的毛玻璃面板。

## 验证边界

遵守当前 MangaFlow 项目流程：只读源码与 diff，不运行测试、编译、本地构建、设备探针或 UI 自动化。最终报告的15项均需分别列实际代码落点和待设备体验条件；源码已实现不能标记运行／视觉通过。

## 本批实现落点与保留边界

来源浏览现为一条对象明确的上下文工具栏；分类、热门标签与筛选各进一个既有 MotionBottomSheet。少量筛选值直接并列，更多选项和多选仍转入完整列表，转场继续等待真实退出再执行。来源选择按「浏览来源／登录后浏览／待处理」分组；这表达本机状态和已知错误，不保证站点在线。

成人聚合推荐的画廊由真实目录决定固定框架，封面解码不再触发向页面顶部插入内容。搜索与成人详情标签采用中性色，搜索标签为12sp并保留44dp触控范围；详情先说明来源，首屏保留六个标签及查看全部入口。原始标签路径、作者搜索和全部标签内容保留。章节分组与站点收藏夹的触控高度也提升到44dp。书架显示实际来源身份和已加载收藏数，分页未结束以「+」表示而不伪装总量。

登录／注册与凭据方式沿用已采用的 Ovio 控件，单一登录能力保持单一展开入口，重复点击当前方式不清空输入。明确的收起动作仍清除凭据输入。账号取消、注册同意、来源代次、秘密存储、站点收藏所属账号与分区历史均沿用原有实现。评论重新分离作者、正文与来源／时间／点赞信息，既有读取和分页行为未改。

`DiscoverScreen.kt` 同时重排原生 Copy 榜单行：68×98dp封面、稳定名次轴、标题与作者相邻，指标继续由同一个 RankingMetrics 提供；没有重算名次或改变周期／分页。

涉及10个UI文件：`AdultZoneScreen.kt`、`ContentProfileControls.kt`、`SourceCapabilityUi.kt`、`SourceAccountControls.kt`、`DiscoverScreen.kt`、`SearchScopeBar.kt`、`SearchScopeControl.kt`、`LibraryScreen.kt`、`DetailScreen.kt`、`DetailCatalog.kt`。`ProfileSiteShelf.kt` 仅阅读，账号归属、恢复和收藏数据契约保持原样。

源码复查包含改动diff、回调签名、commonMain兼容写法与 `git diff --check`。全部15系统的设备／运行／视觉状态仍为**未验证**，由本批总设计文档汇总具体回查动作。

## 以普通漫画为基准的多来源阅读接续

本轮按「成人漫画要补通它已经共用的能力」及「交给你完全落地了」实施，取用同仓库普通漫画的 `UnifiedSourceManager`、`ChapterSourcePicker`、作品关联及阅读备用机制。首要路径是搜索作品、选择原站版本、进入详情核对关联、选择已对应章节的备用版本，返回后沿用当前查询与原来源进度。普通与成人分区以来源登记状态为权威，成人作品关联不会调用普通索引，两个分区继续沿用各自原站的账号与收藏。

| 要求 | 具体落点 | 设备体验 |
| --- | --- | --- |
| 成人详情的来源按钮管理当前作品 | `MangaFlowApp` 将来源按钮接至 `MangaViewModel.manageSources`，在已有来源列表按需展开候选证据、人工查找、章节对应与解除关联。列表只提供同分区来源。 | 从发现、书架或历史进入同一作品，核对来源、返回和原位置。 |
| 搜索候选和作品关联各有权威 | `FederatedSearch` 保留每个站点原始身份，已知冲突作者分列，存在多个候选时供用户选择版本。搜索分组不会写入作品关联。 | 对照相同标题、不同作者和多个版本，选定一条后进入对应站点的详情。 |
| 同分区自动关联与目录复查 | `UnifiedMangaRepository` 在主来源原生目录和候选目录可用时核对完整标题、创作者、已知身份冲突和版本标记。自动对齐使用两端声明的语言并核对目录。单条泛称目录、分册或不一致的语言不自动当成同一章。现有周期检查覆盖成人书架和历史，未收藏或阅读的当前成人作品只在当前进程记为检查候选。 | 比较同作品、不同分册、同名无关作品和未登录来源，观察单源失败及重试。 |
| 备用版本延续实际阅读 | `UnifiedChapterStore` 投影已确认的原站目录，来源管理可人工对应指定章节或拆回独立章节。阅读器只准备同分区、已启用且实际对应当前章节的备选。页位置仍由原版本进度和阅读器原有核对逻辑处理。 | 两端原生目录未证明对应时手动选择一对章节，检查切换、拆分、撤销关联及已有下载与记录。 |

沿用现有主题、字标、Ovio／Motion 控件和来源状态语义。章节对应在同一来源面板内逐步展开，提供章节名称、语言、版本及独立保留动作。当前证据为源码与差异检查，安装后可用性、布局、触控和网络恢复有待设备体验。

## 成人阅读进度跨设备接续

JM 现有 `getWatchHistory` 读取站点浏览条目，哔咔适配器没有公开可确认的精确阅读位置写入接口。精确同步使用项目已配置的 HTTPS WebDAV，独立路径和使用方式见 [WebDAV 阅读备份](../../WEBDAV_BACKUP.md#成人阅读进度同步)。

成人最近阅读的同步按钮打开既有 Motion 面板。选择作品前先展开对应版本、页码和旧长图或当前页内位置的对照。选中作品后保留独有章节，同一版本的冲突和继续阅读位置按明确选择解决。服务端按强 ETag 或新文件的条件写入约束并发。本机重新核对确认时看到的记录和来源范围，沿用 `LibraryStore` 既有写入及恢复机制。远端成功、本机后续发生变化时，界面显示部分完成原因。导入后的现有继续阅读入口按保存的实际原生版本打开。

本段只检查源码及差异。不同 WebDAV 服务的条件写入行为、真机窄屏控件和两个设备之间的实际续读仍待体验。

## 以普通漫画为体验基准的接续实现 · 2026-11-19

用户要求“普通漫画应该成为整个 MangaFlow 的体验基准”，并将体验差距报告交给实现。成人区继承普通漫画的作品、内容和原位回退关系。现有导航将「推荐」「更新」「榜单」显示为主要任务，来源行直接进入「标签」「作者」，站点原生栏目和选项继续按需展开。`ScopedBrowseController` 为每个来源与浏览任务保留原生栏目、筛选、查询和结果快照。推荐呈现真实站点选编与更新，榜单仍分别按站点与周期呈现。作者和标签结果显示站内原生索引、匹配站内分类后使用原生目录、或仅筛选关键词结果中的已知信息。联合检索聚合已有候选，主结果需要版本选择时使用当前搜索的来源选择层，选择结果进入准确的站点作品。

详情沿用共享评论组件。`SourceWorkDiscussion` 只接原始作品与已确认成人关联的作品评论，按来源分栏，分别保留页、滚动、请求失败及恢复。禁漫用固定 JM SDK v1.1.12 返回的 `replys()` 展示随主评论附回的回复。哔咔用 `comics/{id}/comments` 和 `comments/{parent}/childrens` 的独立分页；其路径与 `commentsCount` 字段见 [Venera a04e055](https://github.com/venera-app/venera-configs/blob/a04e055/picacg.js#L635)。复用设备端按需翻译。源账号或代次变化会阻止旧响应覆盖评论。作品评论、回复读取与逐章讨论各自按已证实能力接线。评论发表、禁漫与哔咔逐章评论仍无本轮实现。

来源、搜索、站点收藏或评论需要登录时使用现有来源账号浮层，从原任务进入并返回。原本仅有禁漫的差异核对复用于哔咔默认收藏夹，两个来源共享 `AdultShelfSyncController` 与差异面板。完整扫描后才展示差异，逐项明确选择导入、上传或移除。执行前重核远端与本机清单，原生适配器在账号锁内核对会话。中途出错显示已执行数量并要求重新读取。外站浏览足迹缺少按版本、章节、页、偏移逐项读写的契约，现有本机精准续读继续使用原数据源，站点精确进度同步与冲突处理留待实际接口。

本批继续采用上表的 Motion/Ovio、源标记、颜色、正文尺度与浮层。变化集中于内容导航、来源/版本对象、状态、可局部重试和任务返回。后续设备验收依次查看来源切换保留栏目和滚动、原生能力提示、跨源版本选择、评论页及回复、失败登录后返回、差异核对与中途失败状态。源码与差异检查已执行，未本地构建或操作设备。

## 成人章节的私有讨论

本轮继续补齐逐章讨论。JM SDK v1.1.12 的 `ForumQuery.album` 是作品入口，`novelChapter` 的 `ncid` 适用小说章节。哔咔参考适配器的评论与回复明确使用作品或评论 ID。两站作品评论仍落在详情。 [JM SDK 评论契约](https://github.com/JUKOMU/JMComic-Api-Java/blob/v1.1.12/docs/sources/features/comment.md) · [哔咔参考适配器](https://github.com/venera-app/venera-configs/blob/a04e055/picacg.js#L635)

阅读器沿用本章评论入口、章末玻璃按钮和共享评论正文。成人章节进入明确标注的 MangaFlow 私有讨论。用户在已有 HTTPS WebDAV 账号上主动连接讨论区后，评论只读写该服务器共享目录中的独立记录。该阅读器入口要求经过来源登记校验的原生来源、作品和章节三元组。翻页、切源和普通/成人切换都不能把上一话的请求或草稿交给另一话。读取本话评论与看回复在同一个浮层完成。远端写入只在点按发送后发生，显示昵称、正文与选中的回复对象。

验收覆盖成员使用各自账号和不同备份文件名连接同一目录、相同讨论区名与原生章节。两端应只在对应章读到已发送内容。服务超时保留草稿和请求身份。并发更新须使用强 ETag，进度备份和作品评论仍由自己的入口展示。开启讨论前显示目标服务器与目录，授权由 WebDAV 服务器的目录权限执行。读取只在展开讨论后触发，正文与昵称存放在同目录的章节独立记录里。已核对调用路径与补丁格式，服务器与设备行为留待安装验收。
