# 普通漫画榜单重设计 · 2026-11-19

用户原话：请按审美库原则和十几个系统，对普通漫画榜单深度彻底优化重做重设计。当前基线 `07bf1b85f96b9de9276fe04278e9499d20603e86`。本文件在该模块 UI 修改前形成；授权是实际实现，审美效果仍待用户安装确认。

主线：侧栏漫画榜单 → 选真实站点 → 比较同一口径的名次、封面、标题和关键值 → 进入作品／选择阅读来源 → 返回原榜与原位置。年度获奖属于同一目的地下的独立浏览方式，保持公布年份、正式奖项、实际目录结果与手动身份选择。

目标为 Android 手机／平板和 Windows。首屏以书为重，站点切换与榜种短选项可以比较；复杂筛选只从一个筛选入口展开。没有封面或评分不伪造补齐，当前搜索顺序不宣称全站排名。保留原 controller、数据分区、查询键、取消和持久化。

## 落地与源码审阅

实现文件：`SiteRankingsScreen.kt`、`SiteRankingFiltersPanel.kt`、`MangaAwardsScreen.kt`。删除站点下拉和“菜单 → 组合筛选”的中间交接，站点直接比较，排序／范围／年份／关键词等在同一个保留草稿的面板中；常态页头从三行压到两行。获奖页沿用同一顶栏，两类长下拉改为奖项直接比较与公布年份面板。统一名次轴、68×98 封面、标题作者组和原生评分分母，Android 平板也按行的可读宽度自适应分栏。普通拷贝热榜由负责 `DiscoverScreen.kt` 的同批实施者同步相同排行行尺度。

源码检查已核对：数据模型与 controller 未改，真实查询键与保存位置仍在原 owner；应用后退出通知再释放输入，Info 和筛选互斥；原地重试与保留旧列表分支仍在；`scoreScale` 与缺测文案来自真实字段；奖项年份选择不会自动关联作品，仍从实际目录结果手动选择。未运行任何测试、编译、构建、探针或 UI 自动化。

定点复查：`MangaAward` 三项实际顺序为漫画大赏、小学馆漫画赏、讲谈社漫画赏，连同“全部”与四个短标签逐项对应。榜单／获奖页头轨补上按 13sp 两字加内距计算、且不低于 44dp 的单项内容宽；剩余宽度不足时横向滚动，切换及恢复当前项会滚入可见区，避免将两个命中区继续等分压缩。此项同样仅完成源码审阅，极窄窗口和放大字体的实际触达仍待设备确认。
