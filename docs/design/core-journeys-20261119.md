# MangaFlow 核心旅程 · 2026-11-19

基线为 `e01871d`，对应 Android 0.1.377。用户目标是「搜到想看的，点开就能看，翻页和播放不打断我。多源、网络和缓存的复杂度由软件处理，不由我处理。」本轮的验收对象是普通漫画跨章、成人书架续读和番剧连续播放。

## 三条旅程

| 旅程 | 基线断点 | 采用的交互 | 对照思路和取舍 |
| --- | --- | --- | --- |
| 搜索漫画 → 详情 → 阅读 → 下一章 | 后到的合并目录会替换已显示的目录，卷和章节可能消失。详情的目录动作只能折叠头部。横竖屏改变视口时可能重置当前布局与就绪观测。 | 直接打开作品详情。保留有来源依据或可离线读取的目录项。上次位置定位到自己的卷内。同一版本的坏页优先补页，整章切换须保留真实位置。双页随同一缩放手势移动。 | 也可把所有版本展成分站目录并让用户先选版本。统一目录减少选择步骤，确切卷、译组和版本仍是跨卷与自动回退的前提。 |
| 切到成人 → 搜索 → 阅读 → 成人书架续读 | 切区时，仍在离场动画中的页面可能读取进入分区的列表。成人书架只有一个内容区却显示单选标签，历史与进度入口不清楚。 | 涉及内容可见性的切区立即撤下旧页面。以成人书架标题和带文字的最近阅读动作说明当前范围，续读直接打开保存的章节与页。 | 可以改成全新的独立账号与数据库。采用来源身份及分区组成的隔离，兼容已保存收藏、历史、账号和离线记录，也能避免改库迁移导致丢失。 |
| 搜番 → 选集 → 首帧 → 下一集 | 自动切下一集进行中，界面可能还把重试或来源操作指向上一集。自动关联失败时先弹出整套来源面板，打断点播。 | 控制器持有唯一的正在打开集数。进度、重试、自动换线和手动换源围绕同一集显示。来源管理由设置进入。 | 可以先让用户为每部番选默认来源。直接点播保留更短的正常路径，使用有上限的回退，只尝试已确认的同集来源。 |

## 共用设计

- 复用现有 Ovio/Motion 的选择、过渡和组件，采用现有 Haze 玻璃作为必要的工具表面。阅读画面、目录和视频用内容层级决定焦点。少用常驻诊断，把精确的失败或恢复动作留在发生位置。
- 策略页只展示模式和可设置项，原图范围与近页解码分开。范围、容量与闲置过期沿用各自规则。阅读时从状态栏展开实际准备、补页和命中情况。内存清理在存储管理里操作。
- 应用线路只供未独立设置的请求继承。漫画阅读和章节下载的生效线路分别显示。切换代理提供方不清除原来保存的地址或分类设置，Relay 通道仅在 Relay 被选择时开放。
- 平台和栏目资料量可以不同。能返回榜单、放送、评分或来源目录只证明该项资料可取。播放成功以播放器实际起播为证据。

## 依据与复用

- 已取用当前 [Space 审美库](https://chatgpt.com/space/page_6c522c5579c08191944bb585f4bf5708)、[空间与密度](https://chatgpt.com/space/page_fd2c89948d3c8191b11b87a2de3ed2e4) 和 [MangaFlow 玻璃取用映射](https://chatgpt.com/space/page_c4faa81b88cc8191b00cbe8fd345bedf)。库中实际迁移已存在于项目的 `ui/motion`、`LiquidGlass.kt` 和 `CompactGlassPopover.kt`。这些界面使用已采用的组件与表面；屏上密度与交互还需同视口实看。
- 既有反馈与实现入口见 [Reader 缓存生命周期](reader-cache-lifecycle.md)、[网络界面层级与旧截图](network-settings-hierarchy.md)、[成人书架与查找](../2026-11-18-jm-shelf-search-scope.md)、[Lanerc 迁移记录](../anime/lanerc-port.md) 和 [交接](../ai-dev/PROJECT-STATE.md)。本次取用了这些范围相关材料。历史截图与反馈未能为所有旧版流程逐一还原同条件基线。
- Mihon 的 [读取队列](https://github.com/mihonapp/mihon/blob/main/app/src/main/java/eu/kanade/tachiyomi/ui/reader/loader/HttpPageLoader.kt) 体现当前页优先、页级去重和可用文件观测。Suwayomi 的 [页面处理](https://github.com/Suwayomi/Suwayomi-Server/blob/master/server/src/main/kotlin/suwayomi/tachidesk/manga/impl/Page.kt) 与 [并行搜索](https://github.com/Suwayomi/Suwayomi-WebUI/blob/master/src/features/global-search/screens/SearchAll.tsx) 体现离线优先和分源恢复。Mihon 为 Apache-2.0，Suwayomi 为 MPL-2.0。本批参考行为，使用项目自己的实现。
- [Lanerc 1.1.6 样本研究](https://chatgpt.com/space/page_e184ced85e8c8191985ad8153f1c6375) 记录的是 APK 静态调用链和来源能力；该研究中的模拟器未走通播放。客户端没有可确认许可的原始源码，本批未引入其代码、资源或未核实授权的线路。采用直接点播、渐进反馈、用户需要时才换源的交互思想。[Animeko 的并行找源](https://github.com/open-ani/animeko/blob/main/docs/contributing/code/media-framework.md) 是独立的开源机制参照。

## 交付核对

在有设备时，从已安装正式旧版覆盖安装并保留账号、书架、历史与离线内容。分别走普通漫画搜索与跨卷、成人查找与恢复独立进度、动漫首帧与切集。双页检查横竖切换、锚点和共同缩放，阅读状态检查翻一页后的就绪计数，故障路径检查补页或同一集换线与重试。国内直连只有在对应网络实测后才记为已验证。保留实际版本、耗时和代表性截图，缺失条件单独记录。
