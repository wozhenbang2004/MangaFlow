# 番剧全流程重做 · 2026-11-19

基线：`07bf1b85f96b9de9276fe04278e9499d20603e86`。本轮目标是 Android 手机/平板、Windows 的发现 → 详情 → 选集 → 播放与恢复，并覆盖追番、来源目录、搜索、下载、账号与播放设置。保留真实来源/剧集/线路/会话身份、源能力、观看记录和失败范围。用户亲自安装体验；本轮不做构建、测试、探针或 UI 自动化，源码交付不能写成视觉验收通过。

## 主线与取用边界

发现首屏由封面轮播与续看提供对象，栏目导航仅切换目的地；榜单/新番的条件归各栏目，追番把全部/追番/历史并列，目录只显示选中来源的真实能力。详情首层是作品身份、观看/续看与追番，剧集、简介和评论按需切换。播放画面拥有首要空间，短状态与播放控制归播放器，画质/声音/弹幕等归同一个可读设置层。返回保留原筛选、位置和对象。

实际参考：审美库根页 `page_6c522c5579c08191944bb585f4bf5708` 的 15 系统开工与交付要求；[阴影、层级与材质](https://chatgpt.com/space/page_0e1e13313cfc8191b780e4a0e08d8df8) 的“语义表面”“空间关系”；[交互手感与感知性能](https://chatgpt.com/space/page_4742977a3c64819188a643e2c3db2735) 的输入反馈与位置连续性；[数据可视化与监控](https://chatgpt.com/space/page_b73310d9da448191a55483ec3e429305) 的同口径、缺测与数值对齐；现有 `MotionTabs.kt`（Ovio Minimal Liquid Tabs，81a1bcb），`LiquidGlass.kt`（已采用 Haze 2.1 角色），`MotionDialog`/`CompactGlassPopover` 的保留退出，`AnimeFeaturedCarousel.kt`、`AnimePoster`/`mangaCoverCard` 的已有封面实现。采用现有成熟代码做范围内适配，未声称新界面获得用户审美认可。

## 15 系统开工说明

| 系统 | 设计决定与落点 | 依据与适配理由 | 验收动作与通过条件 |
| --- | --- | --- | --- |

| 排版与可读性 | 标题/次标题/数字三层；观测值与单位分开对齐；长标题限行且完整名保留语义 | 根页排版与监控章节；对应扫读与精确读数任务 | 字号放大、窄窗口下标题/读数/主动作仍可读 |
| 组件与状态 | 少量互斥项用现有 Ovio 分段；追番全部/已追/历史直接可比较；高级设置才渐进披露 | `MotionTabs.kt` 81a1bcb 与根页“选择显示模式”；移除旧蓝字下拉 | 连续切换、返回，选择与真实过滤结果一致 |
| 动效与过渡 | 沿用 Motion 的固定标签/双边界指示与 retained exit；快速反点按当前姿态续接，隐藏内容禁输入 | 手感页“跟手、动效和布局连续性”；避免同对象重新进场 | 快速切换栏目/开关面板，焦点与点击归属保持一致 |
| 图标与符号 | 刷新/搜索/排序/重试/管理均固定 44dp 命中；可见图标带正确名称，选中有形状辅助 | 根页图标规则、现有 MotionIconButton；压缩文字且保留识别 | 触摸、鼠标悬停、键盘/辅助名称能区分每个动作 |
| 图像与媒体 | 轮播与作品封面承担识别；失败占位保持尺寸；小封面不被大面积装饰遮住；视频无设置透字 | 根页图像媒体、现有 AnimePoster/Carousel；保留真实内容和来源路由 | 图片加载/失败、视频明暗画面与面板叠加时可辨识 |
| 导航与架构 | 番剧独立入口；根导航切目的地，详情本地分段切剧集/简介/讨论；播放设置同一容器内返回 | 根页导航与 Motion 现有路由状态；保护浏览上下文 | 发现→详情→播放→返回，位置/筛选/选集不丢失 |
| 跨尺寸与输入 | 并列项按实际宽度及字体扩展，不压缩触控；大屏详情内容限宽，面板滚动受可用高度约束 | 根页适配、现有 LocalMangaWindow 与 BoxWithConstraints | 手机横竖屏、宽窗口、键盘弹出时无遮挡/溢出 |
| 阴影层级材质 | 正文纯净，工具保留液态玻璃；动漫面板在玻璃外壳内提供稳定高遮蔽中性底面，降低视频干扰 | 材质页指出玻璃透明度不等于质量；仅动漫场景加底面，不改全局材质 | 强对比视频上读取设置，文字不与背后视频/字幕混叠 |
| 内容与文案 | “等待视频帧/提交增强帧/暂停/未知”按事实表述；重复说明收进详情；失败给具体重试动作 | 根页文案与监控缺测要求；保护用户判断 | 首层能说出当前状态与下一步，详细口径可查 |
| 手感与感知性能 | 切换指示立即反馈，旧结果不伪装新条件；库/下载不由播放时钟驱动；保留首屏/局部失败恢复 | 手感页三个时刻；复用现有 controller/route authority | 慢返回和连点不抢焦点、不重排已读列表 |
| 数据可视化与监控 | Anime4K 处理尺寸、提交频率、累计提交帧、中间纹理估算按同轴读取；CPU 提交耗时只标 CPU，未测 GPU/呈现 FPS 保持缺测 | 监控页“数值和数据状态要对得上”；采用已有 observation，不增假指标 | 开/关增强、暂停/缓冲/切模式，陈旧值不显示为当前运行速度 |
| 任务反馈与恢复 | 搜索/目录/下载/播放失败归对象；部分成功保留，面板返回与重试保留原对象；下载状态显式区别准备/下载/暂停/完成 | 根页恢复要求、既有控制器回执和 AnimeDownloads；不改任务所有权 | 单源失败、首帧等待、部分下载、离页再返，成功结果仍可用 |
