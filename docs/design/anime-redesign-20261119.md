### 当前实施与证据

- 空统一选集建立时去掉等待更高优先级来源完成的门槛；先有可靠投影即展示，其他来源仍继续核对。已有当前详情的继续观看/指定历史集直接进入同一播放路径，避免重开详情时丢掉有效上下文。
- `OpeningAddresses` 由当前详情和预期观看集持有，沿既有取址过程提前解析少量候选；保存源修订/路由/恢复 epoch/画质等身份和有效期。点击播放保留匹配地址池，来源测量也可共享该池；错误/过期地址仍由正常开播重新获取。提前工作是播放地址解析，不能称为已缓存媒体、已预解码或已取得首帧；没有点击播放时不新建播放器或观看记录。
- 自动开播竞争对原生同源的不同线路允许有界并行，对共用脚本执行环境的 `LanercProvider` 保留源内串行通道。继续沿单一原生播放器、手动首选与同集恢复，不把返回某个 URL 直接标为播放成功。独立审阅发现源修订变化后，按新 key 释放旧竞争通道可能遗留槽位并空等恢复时限；现改为入场候选到固定通道的映射，完成按原候选释放，修正已回查。详情默认集消失、未放送或已无有效线路时及时取消对应取址准备。

### 已读证据、根因与采用范围

源码核对确认：四个首页栏目由 `AnimeController.ensureDiscovery` 组装为应用侧豆瓣查询预设，实际读取 `DoubanAnimeRepository` 的豆瓣推荐接口；它们不是豆瓣下发的一套互斥分类目录，也不是 Bangumi 分类。热门是排序，日/国产是地区，电影是内容形式，将三种维度做成四段等权长页面会造成重复作品、重复错误与切换距离。本批保留豆瓣作为目录来源，改变查询组织与呈现，不能把自定义预设称为豆瓣官方分类。

目录重试的具体断点是豆瓣超时转换成 `AnimeSourceException` 时丢失了可识别的网络异常原因，而上层退避依赖该原因；豆瓣分支也提前返回，没有经过其他资料源的局部重试路径。该源码证据不能推出所有网络故障都来自超时，也不能用无条件无限重试掩盖限流、验证或解析失败。

播放器现有 `AnimePlaybackStatus` 遵守 `visibleMetrics` 选择，问题在于被放进视频下方 transport 的布局高度内，数据越多，选集起点越低。顶部评论入口和片源动作并排，使内容浏览与播放工具混在一处。本批保留用户选择的监控字段、实际统计与既有原生恢复链，只改变承载关系；没有当前证据支持另造播放器或重写自动换线状态机。

- [Bangumi 官方作品/章节合同](https://github.com/bangumi/api/blob/master/open-api/v0.yaml) 支持将作品和剧集分开读取，适合剧集资料补充；这不能证明它的主展示一定更合适。

最小可靠合同为：**主展示资料、稳定本机 owner、远端资料关联、稳定本机剧集/远端集映射分别持有身份**。豆瓣补资料或 BGM 晚到不能重建作品/剧集 key。当前 `AnimeDocumentCodec.subject` 只接受 `bangumi:*` 与 `native:*`，豆瓣 BROWSE 被视频 provider 正确排除；`AnimeLibraryStore.progress` 又全局按 episodeId 保存。因此不可直接套 `douban:*` 或在新 owner 下复用旧 `bangumi:<episodeId>` 后宣称支持恢复。旧 BGM/native 记录首批保持原 key；仅唯一、已确认的同作品关系允许目录入口复用旧 owner。

资料关联优先用明确映射缩小候选，再核对完整名称/原名、年份、格式、季/篇章和目录粒度；同名第一项、暂时只返回一个候选或网络失败均不构成确认。未确认 BGM 时仍能打开豆瓣作品页；若可靠播放目录足以建立本地选集，要显式完成这一当前缺失的能力，不能让 BGM 匹配成为隐形播放前置。每集来源仍来自该集已确认的映射；本集讨论要求精确远端集 ID，作品评论与各站原始评分继续独立。远端追番保持显式目标/差异预览，不按本地集号盲写。

首条正式旅程应为豆瓣发现/分类 → 唯一作品页 → 后台资料与播放源匹配 → 正确选集 → 播放/追番/续看；若真实片名搜索未完成，只能如实称发现旅程完成，不能称默认目录搜索已完成。此前五个 BGM-first 文件撤回后，本轮已按下面的豆瓣合同完成正式实现；旧候选不再作为产品基线。

## 单作品聚合与后台找源 · 2026-11-21

番剧搜索保留原始来源条目，优先用公共作品编号识别别名，再用繁简归一的完整标题与年份判断可共享的卡片。准确标题先显示，已返回的来源保持可用。资料索引确认的别名可以补搜只有无关结果的来源。普通漫画搜索先显示准确标题，同层保留来源热度，并以带来源的原生标识保留命中。

### ANIME-PLAY 源码交付与实际边界

`MotionSlider` 在现有轨道增加默认 null 的 `bufferedRange`，底轨/浅色真实缓冲/深色已播沿同一几何绘制，支持 RTL 与辅助描述。播放器仅传当前有效资产的 `positionMs..bufferedMs`，裁到 duration；拖动预览不改此范围。common seek/重播清掉旧缓冲、缓冲统计和视频统计，拖动预览按 session/timeline 重置。Android 既有 Media3 同步掩码随后恢复真实位置；Mediamp 在发出 Ready/Ended seek 前订阅真实 `SeekCompleted`，完成前拒绝缓冲回执，完成后只接后续观察，不重放缓存值。Opening 不等待不存在保证的完成事件。Windows 原生 IO 统计也增加 timeline 返回守卫。暂停定位若没有新原生缓冲观察，保持未知而非补回旧终点。

新增默认可见的“丢帧计数”，沿现有观看读数开关、原生采样和状态详情接通。Android 使用 `droppedBufferCount`；Windows 将解码与视频输出计数分开。真实 0 和缺测 — 分开，明确原生计数可能随定位/重建重置，不称本集总计、不生成百分比。v1 非空番剧显示集合补入新项；明确隐藏全部保持；显式保存为 v2 后关闭选择持续有效，漫画显示偏好不变。输入尺寸与增强提交尺寸同时可见，后者不称屏幕实际呈现。

`EnhancementScaleCapabilities` 读取现有库存和执行路径：Anime4K S/M/L/VL/UL 的真实 Restore 1× 与 Restore+Upscale 2×；CUGAN/ArtCNN 仅 2×；ONNX/JaNai 按所选权重 nativeScale 与对应就绪引擎相交，RIFE 不贡献画质倍率。自动档保留当前模型优先级、在线与实时 MODEL/RIFE 的互斥；静态能力不随短期温度/内存跳动。旧无效倍率保留并提示，不假高亮首项；模型列表/详情预告“选用并改为 N×”，点击时按最新库存复核并一次保存模型及兼容倍率，不修改档位或别的设置。模型导入页的倍率是导入声明，仍与已知模型的输出选择分开。

片源页先给本集实际解码和真正可选清晰度/轨道，未来开播偏好进入原面板子页；返回偏好→片源→画质，保留播放准备入口归属。1×/2× 的像素含义、p 与 FPS 的区别均就地说明。没有发现固定 1920 解码宽度上限；用户截图只证明 1080p 输入与 2160p 增强提交尺寸，不能证明最终增强成功。缓冲默认 50 秒补充阈值/120 秒目标上限沿原策略，时长可能先受字节预算、网络及片尾限制；观看文案明确“前方缓冲”，设置区分别说明补充阈值、上限、起播和恢复。

### ANIME-PREP 实施与源码交付核对

**统一归属与清理。** `StorageCacheStore` 继续作为唯一协调入口。两端原片 owner 逐资产返回来源、作品、集数、实际文件字节和保护状态；`StorageManagementDialog` 沿缓存类型→作品→来源（同作品多源时）→集数逐步披露，沿原选择／确认／结果流程清理。原片、离线原文件、增强结果、进行中的临时文件分别计数，未归属目录余量按受保护未知项显示。离线原文件包含实际部分下载占用，不参加自动缓存淘汰；番剧下载与漫画下载各有准确返回入口。应用初始化注册持久增强及原片 owner，无需先进入番剧页；Windows 在线工作文件也交给该协调器显示及清理，活跃窗口保护到滤镜或进程真正释放。

原片的当前播放、下一集准备和在线处理各持有确切资产租约，不再因任意番剧播放保护整个缓存目录。Windows 持久 span 缓存只命中完整请求区间，开口 Range 的一个短前缀不能冒充整个余下视频；损坏资源在当前桥内旁路并交回原恢复路径。冷启动尚未恢复预算与用户明确零容量分别处理。各 owner 清理前重查 revision／租约及当前目录，释放量使用实际前后字节差；文件已消失不算本次释放。

**当前缓冲与下一集。** `AnimePreparationBudget` 只是既有体验策略的纯投影。时长、前方容量、回看容量、下一集提前量／时长／字节及首帧开关均在现有设置、持久化和控制器内生效。Android `AndroidAnimeLoadControl` 保留 Media3 1.11.1 allocator 和生命周期，动态更新支持的参数；请求达到真实 JVM 最大堆时保留上次有效目标并说明，持久化手动数值不改写。Android 没有回看字节目标接口，明确报告此能力边界。Windows 更新原 mpv 参数。两端诊断把保存值、原生执行目标、实际压缩包分配及缺测分开；不把压缩包缓冲叫已解码帧内存。

接续交付采用普通漫画作为体验基准，依据用户本轮「交给你完全落地了」及[体验差距研究](https://chatgpt.com/space/page_8da8196d6f14819180de20561b2d9a84)，基线 `2a65502`。详情取用普通详情的真实封面、短渐变与优先续看动作，控制沿用现有 Motion/PANEL。播放器设置固定在标题行，取址、失败、暂停、播放均保留同一入口。设置按当前目标集显示准备阶段，只在已绑定当前媒体时读取运行指标。清晰度目标优先使用来源提供的明确选项，仍可在播放时手选。下一集沿用已确认线路、原有资源许可与可复用播放器缓存，以实际地址、字节及可起播证据分别表达。
