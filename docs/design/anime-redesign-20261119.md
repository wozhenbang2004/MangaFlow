## 点按全屏自动横屏 · ANIME-ROTATE-01–03

用户原话：“看房的时候能不能加一个按钮，放大之后全屏就自动横屏啊？你的竖屏看法模式。”记录日期 2026-11-19（Asia/Shanghai），消息 ID 与安装版本未提供；结合当前番剧播放上下文，将“看房／看法”理解为“看番”，已向用户说明从竖屏看番点按进入横屏全屏的解释。基线 `eac0cb8`。源码确认原全屏只改变 `playerFullscreen` 布局，没有 Android 方向请求，按钮还受播放器 READY 状态限制。

ANIME-ROTATE-01：非全屏播放区底部右侧提供现有 Fullscreen 图标按钮，与轻状态同一行，固定 44dp 命中范围，不占用状态横向滚动区；取址、加载和失败阶段仍可放大。全屏保留顶部退出动作及系统返回，复用同一个全屏状态。02：Android 点按全屏申请 `sensorLandscape`，记录进入时的实际方向，退出回到进入前的横／竖屏模式；离开播放页、页面失去活动权或进入画中画时恢复原来的方向策略，画中画返回保留进入前方向。03：复用现有播放器和 native 视频表面，不重建媒体、不改漫画 ReaderWindow，不改变 Windows 的窗口方向行为。

本次是现有播放器的局部交互补齐，沿用上节已选 Motion 控件与图标。实施前核对：空间与密度将进入动作放到播放区右下角；组件选择与控件状态去除播放就绪限制，保留遮挡／锁定／PiP 门控；图标与符号使用现有全屏／退出全屏及辅助名称；导航与信息架构、任务反馈与恢复共同覆盖按钮、返回、离开页面与画中画；跨尺寸与输入适配保留 44dp、状态横向可达、安全区和 F/Escape；图像与媒体保持同一播放表面与实际比例。配色与表面关系、形状与圆角、排版与可读性、动效与过渡、阴影层级与材质、内容与文案、交互手感与感知性能、数据可视化与监控沿用已采用实现，不新增样式、动效或数据采样。

平台依据为 Android 官方 [Activity.setRequestedOrientation](https://developer.android.com/reference/android/app/Activity#setRequestedOrientation(int)) 与 [ActivityInfo](https://developer.android.com/reference/android/content/pm/ActivityInfo#SCREEN_ORIENTATION_SENSOR_LANDSCAPE)。Android 16 起目标 API 36 的大屏可能忽略方向请求，继续使用现有自适应全屏布局，不为该按钮改应用兼容性开关。项目仍只做源码与差异审阅，直接 main 并确认 CI 触发；手机旋转、退出、画中画、视频连续性及输入效果均待实际安装反馈。

源码交付核对：进入按钮已移至状态条右侧的独立固定位置，不再依赖播放就绪；Android 的方向申请只在活动播放器生效，PiP／离开时恢复，非 Android 为空实现。返回方向仅首次全屏记录，避免快速退出再进入时把尚未完成旋转的横屏误存为返回方向。独立只读审查核对了平台覆盖、返回／PiP、保存状态和旋转前后的稳定 composition 路径；本节所列受影响系统完成源码核对，所有目标设备效果仍未验证。

### MEDIA-STATUS 源码交付核对

`ReaderScreen` 将既有当前普通/成人 reader controller 的状态和策略传入四槽；`ReaderExperienceStatus` 的任务计数只把实际 running 加入活动数，合并等待/排队但不冒充执行，并在预读与任务明细增加画质处理、当前窗口已备、整页耗时与原中心入口。四阶段图例和方向相关的“前方增强已备”文案同步更新。浮层真正退出后才打开增强中心，中心/对比显示时状态栏退出。原图与增强缓存没有合并成一个虚假总量。

`AnimePlaybackStatus` 直接读取当前 asset/episode 的播放器字段，没有新增观测循环。实际呈现 fps、源 fps、补帧活动、缓冲和前方预处理片段分别命名；暂停/缓冲时不沿用瞬时呈现值。`AnimePlayerSettings` 保存具体的增强入口页，状态条能直接进入画质、补帧、缓冲与预处理。`AnimePlayerPane` 为视频内容与覆盖控件同时提供正确内容色，常驻轻状态与可收起控制分离，恢复动作和低频设置保留。
