# 阅读缓存生命周期：范围、容量、过期分别负责什么

## 事实与迁移

旧实现对活动阅读章节整体保护，超过前读/回看范围只会退出准备队列，不等于删缓存。内存是 Coil 可复用解码 LRU；磁盘是可再生成原图/衍生图片，离线章节不属于这个可清理存储。范围淘汰不再通过改数字或仅增加一个 UI 开关模拟。

新增 `contentCache.memoryOutsideWindowCleanup` 和 `diskOutsideWindowCleanup`，分别控制两种范围回收。内存缺省 true（旧配置缺字段也启用，只减少解码复用）；磁盘缺省 false（保留原图，避免升级后突增重复联网）。已明确保存的 false/true 均尊重。旧配置容量与过期策略保持，不清用户存档，不改离线目录，不重写缓存索引版本。

## 四种不同动作

| 动作 | 内存 | 磁盘 |
| --- | --- | --- |
| 离开阅读范围 | 可选移除已识别的可复用解码条目 | 可选删除已识别的可再生成图片 |
| 达到容量 | 既有硬容量及 LRU 继续生效 | 共享容量整理与可选写入准入生效；保护中的内容可暂时超额 |
| 未使用到期 | `memoryIdleMinutes`，0 表示不额外按时间清理 | `imageRetentionHours`，0 表示不额外按时间清理 |
| 手动清理 | 移除复用条目，不销毁显示者持有的图像 | 仍逐项验证版本、访问和保护条件，不强删使用中的资源 |

保留旧名的 `automaticCleanup` 现只控制磁盘自动过期，不控制容量整理或范围清理。关闭范围清理只停止“离窗”这一触发，容量/到期仍可回收安全的窗外条目。容量整理始终沿共享协调器保护门禁执行；Coil 独立 LRU 已禁用，不能宣称存在不顾活跃资源的硬上限。磁盘淘汰顺序不代表内存也有相同可选顺序。内存范围回收计入独立 `rangeEntries/rangeBytes`，不伪装成人工清理或容量淘汰。

## 范围的真实定义

活动阅读布局发布当前可见页、主方向前读、回看、独立解码准备、仍由布局持有的图像和已提升前台任务的并集；主方向使用两逻辑页意图策略，因此单页回看不会立即把长窗翻侧。额外仍被解码/前台使用的页可以晚于数字范围回收，不能为满足页数强删它们。

每个阅读会话以精确缓存身份登记身份到页集合，一张共享图片可对应多个页。当前完整 manifest 登记之前保守保护整章；持久索引中的单个 pageIndex/chapter 字段只是说明，不能单独授权删除。只有当前会话实际进入过保留窗口的身份才成为范围回收候选。离开会话仅撤销其保留，并交接这些已识别候选，不扫描清空整章。

HTTP 图片由当前 manifest 的请求缓存 key 登记；脚本/JM 文件先有实际文件租约描述，再由当前阅读 owner 的真实解析/加载结果授权范围映射。旧后台 manifest 或租约不能给新会话标记 ready 或取得删除权限。未知身份、未知页、未知所属映射继续保留。其他阅读会话、来源修复/准备会话仍按其保护保留同一资源。缓存 key 保留来源、账号会话、请求头和转换身份，不能按裸页码/文件名猜测跨源相等。

## 删除前的安全门

范围清理和容量回收共用文件所有权保护。每次实际删除再次验证：当前开关、是否仍在范围外、全部会话保留并集、真实文件租约、下载任务、最近访问交接保护、文件时间/长度/原记录访问时间。Coil 的原图快照和 editor 也必须释放才可删除；离线文件根本不在可选后端中。

内存只调用缓存的精确 key remove，不 close/回收显示者、解码器、原生层持有的对象。最近 30 秒复用过的条目保留，当前会话保留的 key 不参与。磁盘原图消失后，已知内存别名仍可由独立内存策略回收，不把两开关绑在一起。

## 时机和用户代价

窗口/文件租约变动唤醒维护，纯内存范围变动走独立轻量任务，不为了每次翻页扫描整个磁盘目录，现有约 1.5 秒合并调度不变；最近访问/文件交接保护约 30 秒，保护结束后再尝试。活动采样亦最多每分钟补查一次。因此“离开范围”表示成为可安全回收候选，不保证下一帧立即清零。当前使用、在途、离线和未知归属不会为了达到数字而被强删。

开启磁盘范围清理后，回看超出保留范围的页可能需要重新联网取得原图，并重新解码。只清内存通常可从磁盘重新解码，不必联网。缓存字节减少不等于进程 RSS 立即下降；画面对象可继续由显示层持有。

## 验收边界

本片未运行本地构建、自动测试或设备验收。合并前静审；之后需验证单页回看/长跳/换章、双页、模式交接、相同 key 多页、多会话、来源替换、下载抢占、未知归属、关闭开关期间的在途清理、文件版本变化、离线保留、两开关各自开启及容量/到期的独立触发。不能把静审或计数变化当成实际无重传证据。

## 后续：设置变化时停止旧自动批次

共享 Store 的自动过期/容量扫描使用同一配置快照（开关、TTL、预算及对应发布世代）。实际删除前再次核对，不把旧扫描候选套用到新设置。Coil/普通文件在删除门禁检查；资料缓存 owner 在自己的文件锁与身份校验后检查；番剧缓存每个 span 检查。番剧本轮候选上限不会提前发布，最终经配置锁原子校验后才发布新的容量目标；失效则保留上一已发布目标并唤醒新维护。活跃播放器期间不删除 span，释放后重算共享预算。

这是阻止尚未开始的旧自动删除，不是回滚已准入的单项删除。手动清理仍使用用户确认过的快照和原有使用/身份保护，不受自动批次配置门禁控制。磁盘容量是保护约束下的整理目标，不保证瞬时硬上限；关闭自动过期不关闭容量整理。

关闭磁盘范围清理后，窗口移动若释放了受保护资源且最近测得容量已达上限，仍会唤醒容量维护。没有容量压力时，纯内存窗口更新不额外扫描磁盘。此改动不改阅读器或跨模式原图所有权；仍未进行本地构建、自动测试或设备时序验收。

## 后续：缓存观测不能因局部内存压力终止整章准备

阅读窗口的观测和预检是同一准备协程的子任务。原有原图观测只捕获 Exception，Android 图片头/EXIF 读取产生的 OutOfMemoryError 可越过该边界，取消父准备任务；页号变化并不是该任务的重启 key。这是代码层面的失效路径，不是对用户设备已经发生 OOM 的诊断。

原图观测现把预期 OOM 保留为“未知”，不说文件缺失；可复用预检的字节/解码工作在 OOM 时返回“暂缓”，继续遵守既有准入、容量和间隔。暖预览 flight 的原有 finally 仍完成等待者并撤销所有权；原图 snapshot、解码准入和文件锁依然由原有 finally/use 释放。不吞取消或其他致命 Error，不把未知变成功，不新增网络重试，也不把整个任务改成忽略错误的监督域。未运行设备复现、构建或自动测试。

### 后续：手动磁盘清理后的内存引用保护

手动清理仍以用户确认的磁盘快照为准。某项磁盘文件实际删除成功后，对应解码复用引用在 Store 的保护锁内重新核对所有会话、租约及未知别名，再精确移除；不再在整批磁盘操作返回后凭旧 `removedKeys` 独立删除。新进入阅读范围或同别名被另一资源保留时，允许磁盘结果与内存结果不同，保留该复用引用。此步骤不受范围自动清理开关控制，也不会关闭显示中的图像或删除离线文件。实际命中的内存移除计入“手动清空”，不计作范围回收；磁盘清理返回的字节数仍仅表示磁盘字节。

此修复依据代码竞态与别名调用链静态审查，未宣称用户设备发生过该竞态，也未验证设备实际回收时延。

### 后续：范围清理关闭再开启的精确内存映射

关闭内存范围清理只停止该触发，不丢弃已证明的资源与内存 key 对应关系。已进入真实阅读范围的资源在磁盘原图被清掉后，仍可保留短期内存映射；退出会话保存的仅是精确 `windowSeen`，不根据章节号补全授权。重新开启后使用同一全会话保护并集判断，不把未知来源、离线文件或旧章节标签视为可删除证据。

映射仅进程内保留，最多 2,048 个资源、每项 64 个别名、合计 8,192 个别名及 1,048,576 个 UTF-16 字符描述。达到上限时不扩大授权，超限缓存仍由普通容量/闲置机制管理。纯内存 key 快照会剪除已确认消失的映射；未挂接或读取失败不当作空缓存。历史范围授权另限 20,000 项，超限仅放弃旧授权，不删除实际图片。

不重建或弱化现有 key：带来源/凭据身份的 Coil key 沿用 `readerPageCacheKey` 的 source/revision/session 字段；脚本物化文件使用已有 source owner、bundle、账号 epoch、URL/变换/headers 指纹，原生 JM 使用其现有图片指纹。公共图片仍按其原 key 分享，跨资源共用 key 继续经过受保护别名并集，不能宣称所有公共源都含账号 epoch。未进行设备开关切换/回收时序验收。


### 后续：容量与到期触发真正分离

旧 `automaticCleanup` 持久字段和值保持不变，迁移后只表示“自动清理过期缓存”。旧值 false 继续不按时间自动删除，但不再停掉容量整理。图片、脚本、原生 JM、Android 动漫以及已挂接资料缓存继续由同一总占用预算选取可安全清理项；范围开关独立。目录、浏览/排行、动漫资料的局部容量整理也不随过期开关停用。共享 Store 的容量与过期批次各有显式触发类型，删除前仍核配置世代、预算和保护状态，手动清理不被误取消。浏览/排行/动漫资料各自写入后的局部整理逐项读取当前配置，属于单项准入，不宣称拥有 Store 的跨批次配置事务；已准入单项删除不可撤销。

纠正旧说明：Coil delegate 使用 Long.MAX_VALUE，由共享协调器负责保护性整理，原先“关闭整理仍有 Coil 硬上限”不成立。Android 动漫初始化会通过 attachAnimeCache 获得初始预算，并非首次永远无限；原缺陷是关掉旧开关后不再按新预算及其他缓存占用调整。现在容量分支持续运行。活跃播放器原生 span 回调也遵守会话保护，不能为了满额删除正在使用的内容；最终 release 唤醒重算，不在活跃期间自循环重试。

磁盘预算是受保护约束下的整理目标，不是瞬间强制上限。所有可清理空间都被阅读、播放、下载或在途租约占用时允许暂时超额；可选预读仍受已有准入控制，前景不因强制删除断流。播放器/系统内存或非应用管理的流缓存不伪计入磁盘占用。内存图片 LRU 容量仍独立真实执行。此次为静态代码审查与保护门禁修复，未进行设备容量/播放验收。
