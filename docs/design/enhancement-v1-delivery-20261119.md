## 漫画／番剧两类设置 · ENH-UX-08–11

2026-11-19（Asia/Shanghai），基线 `f00cef7`。用户原话：“而且我不理解啊，你为什么要把那个佛陀曼车曼翻句分别弄三个 type来设置它们的那个画质增强？不正常就只有很离谱啊这个设计好吗？要么就漫画，要么就动漫啊。动漫就画质增强补正啊，漫画就是画质增强呀。你都不知道为什么会搞这么复杂，那个 UI Unix也是非常的恶心”。消息 ID 和安装版本未知；按同轮上下文理解为批评普通漫画／成人漫画／番剧三套增强设置，“补正”指补帧。已向用户说明按漫画／番剧两类实施。

本节替代上一批普通／成人各自保存增强默认和观看显示项的决定；原分区、会话、任务、缓存、历史身份继续隔离。原话并未要求合并书架或重写增强算法。UI 将数据分区枚举直接当成设置分类，是本次已定位的设计错误；不能只删一个 Tab 而保留后台两份默认配置。

- ENH-UX-08：全局只有“漫画／番剧”两类。漫画提供画质增强，番剧增加补帧。阅读、播放和下载入口直接进入当前媒体类别，不再让用户重复选普通／成人。沿现有 Ovio/Motion 选择、单一面板与对象详情，不增加 UI 家族。
- ENH-UX-09：漫画默认策略和观看读数各只有一个持久化归属，从普通或成人入口调整默认都发布到同一值；本次阅读覆盖仍按真实内容与 session 精确匹配。下载消费者通过同一 Store 自动获得共享默认，处理资产、任务、租约和缓存目录不改。
- ENH-UX-10：全局设置专注两类配置，无当前会话时“状态”页直接提供观看显示项；当前任务、缓存和运行／试用数据留在阅读、播放或下载的上下文入口，避免唯一“漫画”分类下只统计普通分区却冒充全部漫画。显示项选择不重启处理。
- ENH-UX-11：旧配置读取优先新共享键、有效普通漫画旧值、有效成人旧值、内置默认。没有时间戳，不声称采用最新值；两份旧值原文保留，不覆盖或删除。旧显示空集合是有效的全部隐藏。共享默认改变时，结束同漫画类别且正在继承默认的性能记录；独立会话覆盖不受影响。

## 增强操作与观看读数重排 · ENH-UX-01–07

2026-11-19（Asia/Shanghai），基线 `8e20e35`。用户原话：“现在这个U1UNX我很不满意啊，就是关于画质增强这一块，对吧？什么补帧啊，对吧？做的很烂。还有就是选模型那里，妈的，那个全部跟文档一样铺在上面，乱七八糟。就是各种乱呀，我们的各种原则你都忘了吗？什么格式塔呀，信息层级啊？那些东西你都忘了吗？瞎搞嘛做的”。随后明确纠正：“而且我们要求了那个数据啊，就是那个补针啊，什么增强啊，那些数据是我要在看发的时候可选的显示出来的，而不是他妈的搞个菜单在那里，我还要点菜单才能看，懂我呢？我看漫画的时候你没把这个东西加进去啊，也需要加的。它本身跟预读是一个原理啊，”。消息 ID 与实际安装版本未提供；按上下文将“补针／看发”理解为“补帧／看番”，已向用户说明。此前截图与本次源码可作问题依据，没有本次改版的安装后图证。

主线分为观看与设置：观看时所选增强读数直接可见；需要改变处理方案时进入画质／补帧／预处理／状态，在对象所属页完成选择，再回原阅读／播放。普通与成人漫画共用交互、保持各自内容身份。ENH-UX-01：漫画改为画质／预处理／状态固定页，番剧保留四页，首层只留本页决策与必要障碍。02：模型为去重的紧凑候选行，真正选中、已安装与缺组件分开；说明、许可、摘要、来源和运行组件进入对应详情。03：输出倍率／内容类型／锁定和补帧质量各有所属参数页，不再在首层堆展开长文。04：漫画及番剧的增强／补帧／准备读数按内容可选，选中后在观看界面常驻低干扰显示，菜单只负责选择显示项与深入诊断。05：真实帧率、处理吞吐、文件已备与最终呈现口径严格分开；原图、前方增强、队列和资源都使用既有 owner 的观测。06：下载失败可重试，下载／导入不把旧页面草稿回写到新的作用域；补帧文件按既有质量映射，不伪造独立 frameModelId。07：保留同一设置保存队列、普通／成人隔离、缓存租约、原画可用、播放器会话、退出和比较交接。

采用并已实际读取：审美库空间布局的“列表与跟随详情”“设置与分组表单”“空间预算”、视觉与交互的文本角色／安静工具面／表面关系，控件系统第四至七章的选择基数、集合→对象→动作、按需披露与状态区分；沿用 Ovio `81a1bcb` 的真实 liquid-tabs/use-liquid 原码适配、当前 MotionIconButton/MotionTextButton/MotionTabs、SettingsToggle 和 EnhancementPanelHost。具体组件与调用位置已查看；不新增 UI 家族，也不以单纯缩字或全体折叠替代层级。监控／任务恢复系统用于真实读数、缺测和失败现场。以上属于项目采用，未声称本次视觉已获用户认可。

## Anime4K 扩展和 Vulkan 前方画面

Android 与桌面可按需安装 Anime4K L/L、VL/VL 和 UL/UL。各组合保留上游真实系数，安装校验原版文件。它们用于自动、轻量、均衡的基础实时路径，1× 只加载修复，2× 增加放大处理。精细及极致保留高质量模型。选择模型不再修改已选输出倍率。

Android 的 Real-CUGAN Vulkan 2× 接入同一前方画面缓存。兼容的 SDR 点播在原线路读取预算内预解码并生成增强结果，实际播放仅在原解码时间戳和画面签名同时匹配时使用缓存。前方窗口仍受设备压力、处理时限与无损缓存预算约束。

实时 Real-CUGAN 可在兼容的 Android SDR 视频单独开启，或与已安装的 Vulkan RIFE 组合。两个组件计入同一播放资源配额。运行状态分别显示实际生成速度、输出时间轴和单帧处理时间。原帧率与原图各有独立的回退路径。

自动补帧从 Android 当前 Activity 的显示器或 Windows 实际播放窗口取得刷新率，并结合源帧率确定目标。运行状态单独展示当前屏幕刷新率。无法取得显示器回执时，可选明确的输出目标。

## Android 实时 Vulkan RIFE

均衡实时补帧使用官方 ncnn RIFE v4.6。签名 Vulkan 组件与权重均按需安装，原生实现按真实 VkMat 推理、逐张校验 RGB 输出。Media3 将新 PTS 与源音频时钟一起排程。2× 根据源帧间隔补帧，60 / 120 FPS 使用固定目标时间网格。跳转清除上一对输入，切镜、相同帧和长间断保留稳定的原画组合。运行状态分别显示生成帧、处理链输出频率与屏幕呈现指标。

当前实时试用范围为 SDR 720p、最高 60 FPS 的源视频。使用原始首帧，然后接入实时效果。连续超预算或 Vulkan 失败时恢复源帧率。Android 离线的 v4.25 Lite、v4.22、v4.26 仍可独立选用。两类路径的模型和质量映射分别披露。

## Windows 专用 AnimeJaNai 实时播放

Windows x64 可选安装官方 mpv-AnimeJaNai 3.12.3 与 HD V3.1 Performance、Balanced 两个真实模型。官方播放库在独立目录与应用内同版 Mediamp JNI 组合，校验官方归档、单个文件和原装 JNI 依赖。首次按需载入新内核前记录启动标记。上次启动未产生首帧时，下次会先使用原装内核。Android 与非 Windows 平台不会加载这些组件。

同一 Windows 组件包含独立的 1× TemporalFix S1 v1.1 时序修复。滤镜需要实际返回该时序模型的回执，再按实际输出尺寸确认执行。安装保留上游许可。APISR 的学术用途限制仍需单独解决，当前安装目录不含 APISR。

同一播放器内的原生滤镜处理 D3D11 SDR 视频。滤镜模型回执、原生输出尺寸与实际时间轴变化共同确认超分生效。独立的均衡 RIFE v4.22 下载可用于原画补帧，也可与已选超分组合。2×、60、120 FPS 和自定义帧率按片源帧率求比例，保留原播放器的音频、字幕和跳转。在完成模型加载或取得滤镜输出时，界面仍分别显示状态和输出帧率估计。

Windows 的其他 RIFE 质量继续使用离线模型。实时 RTX 5060 性能、最终屏幕帧率、Windows 同源前方增强帧复用仍待闭合。当前 Windows 实时路径使用 DirectML，TensorRT 原生内核和目标设备的能力需单独验证。

## Android Vulkan 漫画增强续接

Android 新增官方 Real-CUGAN NOSE 2× 无降噪模型，供彩色漫画和条漫选择，并沿用普通、成人各自的衍生缓存和当前页、临近页、整章准入。ncnn Vulkan 运行库按应用进程架构通过已有签名目录选装，模型安装校验官方 `.param` 与 `.bin` 的固定大小和摘要。每块以原版 18px 镜像边界进入 ncnn Vulkan，JNI 在确认硬件设备和推理层之后，用 `VkMat` 中间张量完成真实计算。完整 PNG 仍经原文件、模型和像素尺寸校验，再交给原缓存所有者。

依据用户追加的「画质档位与放大倍率分离、补帧独立、最高档使用真实高质量模型、预处理优先」及天玑 9400 / RTX 5060 的目标设备。

- Android 即时高质量尝试需要兼容已安装的 RGB ONNX 图片增强图、可用的 NNAPI 硬件执行及当前帧预算。处理路径与执行提供方按实际回执判断，失败保持可播原画。NNAPI 硬件结果与 Vulkan 或具体 GPU 指标分开。

- Windows 实时 ArtCNN C4F16/C4F32 是上游固定的 MIT 权重与 GLSL，实现真实 2× 亮度超分。仅在 libmpv 反馈对应的 GPU 绘制阶段时显示实际执行。Windows 高质量整集处理继续用 VideoJaNai，Android 与 Windows 的已下载版本保留原始版本及回退。

## 已完成的静态交叉审查与修正

1. 高级档缺模型时不使用 Anime4K M 或非神经滤镜冒充。Android ONNX、Windows 专用模型显示真实内容/倍率/许可和设备未验证状态。
2. 普通、成人衍生缓存的 LRU 只处理自己的 namespace。Coil 与每次原生 tile 解码各自保留文件租约，不能依赖先退出的 UI 租约。
3. COMPLETE-only 查询已有增强缓存；缓存未命中不能偷偷开始实时推理。整章与阅读缓存共用相同规范化 tile/overlap、引擎版本和源摘要。
4. 关闭会话、恢复默认后，已经排队的设置写入不能使旧会话覆盖复活；试用保存串行化，失败回执可见。
5. Windows 原生取消保留已观察子进程句柄，确认退出后才让调度器释放资源；用户取消与重试不覆盖原文件。
6. RIFE 切镜检测阈值零不代表关闭。本批始终使用 0.15，精确绑定当前质量所需的真实权重文件。
7. 离线增强版标记为已处理文件，避免再次叠加 Anime4K；其 FPS 不冒称原始片源 FPS。
8. seek/暂停使旧 GL 观测 epoch 失效，GPU 查询在 GL 线程重置，Main 消费回执再次守卫；GPU 查询检查有效 counter bits 并拒绝可能溢出的长窗口。
9. 实际模型或输出尺寸改变后重新统计视频耗时；漫画前方任务只更新处理统计，不把下一页的模型冒称当前页模型。
10. 下载中各版本的播放入口共用关闭面板后的导航路径；全局番剧缓存入口初始化同一实际缓存所有者，不以空引用返回“清理成功”。
11. 合并 main 的两处冲突保留新主线的 AnimePanelSurface、按作品分组、真实下载进度、删除菜单 presence、AnimeChoiceStrip 和原有设置分组。

本批只做源文件、接口、调用点、官方固定源码/协议与差异审阅。`git diff --check` 无输出不代表编译、运行、视觉或性能通过。没有编写/执行测试，没有本地构建、模型安装、媒体转换、基准、API/设备探测或 UI 自动化。正常 main CI 触发及其真实链接单独在交付消息中报告，不推断构建成功。

## 设备验收仍需覆盖

Android 与 Windows 应分别使用同一真实页面/片段验证选档、原图先显示、增强替换、放大与滚动锚点、不同漫画内容、条漫接缝、翻页/seek/切源失效、前台争用、缓存清理与正在使用文件保护。Windows 还需验证 RTX 5060 实际模型、编码、音轨/字幕/章节保留、离线版本切换、暂停恢复和长任务。120 Hz 手机及 60/120 FPS 输出要分别记录实际呈现、丢帧、温度趋势与短时样本时长，不能用配置目标或输出文件头替代显示测量。
