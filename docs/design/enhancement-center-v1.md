# 画质与性能 V1 · 设计与验收记录

日期：2026-11-19。源代码基线：`07bf1b85f96b9de9276fe04278e9499d20603e86`。

## 用户主线与边界

Android 天玑 9400 / 120 Hz 与 Windows RTX 5060 用户首先需要继续阅读和播放。全局设置的「画质与性能」保存普通漫画、成人漫画、番剧各自默认值；阅读器和播放器只展示当前内容相关的参数，并允许一次会话覆盖。进入面板先看当前结果、所选目标和下一步，随后才展开模型、资源和测量。关闭面板继续同一页或同一时间点。

画质档位与倍率、运动补帧与目标帧率、处理时机分别建模。最高档可以选择；没有运行引擎或权重时保留明确原因和实际安装入口，不能伪装成已执行。所有运行数据来自对应会话的实测；未采集显示「不可用」，尚未产生显示「等待观测」。选择、安装、执行、完成、校验和实际呈现分别表达。

| 排版与可读性 | 标题、值与单位、说明分三级；测量按行对齐 | 用户要比较实际速度和代价 | 清单「排版与可读性」；当前 Material typography 与数值格式器 | 继承字号角色，不缩小关键状态来塞内容 | 大字号下可换行，数值与单位不歧义 |
| 组件选择与状态 | 少量互斥档位使用 MotionTabs；多选处理时机使用独立开关 | 可同时比较，且时机可以共存 | 清单中的 Affect 分段选择示例；`ui/motion/MotionTabs.kt`，Ovio `81a1bcb` | 使用 Soft 处理；六档在窄屏分两行，避免下拉 | 快速切换后保存值、目标值及真实状态分别正确 |
| 动效与过渡 | 一个可逆的底部/侧面面板；详情局部展开，焦点跟随当前范围 | 避免播放中弹窗套弹窗 | `MangaMotion.kt`、`MotionTabs.kt`；手感系统「跟手、动效和布局连续性」 | 复用时长、弹簧和减少动效偏好；离场期间禁止输入 | 快速反向、关闭、返回不跳位，不穿透点击 |
| 图标与符号 | 图标表达画质、准备、缓存与比较，文字保留档位和错误 | 模型术语不是大多数用户的任务 | 清单「图标与符号」；现有 Outlined 图标与 MotionIconButton | 统一 20dp 符号及 44dp 触控区域，提供辅助名称 | 同义动作符号一致，键盘与读屏可辨认 |
| 图像与媒体 | 原图先显示；比较仅允许同身份、同页/同帧的原始与增强结果 | 比较必须真实且不改变阅读锚点 | 清单「图像与媒体」；现有原图/缓存对比路径 | 不用示例图冒充当前处理；尺寸来源明确 | 换页、seek、切源后旧比较结果不进入新内容 |
| 导航与信息架构 | 设置唯一全局入口；播放器/阅读器上下文入口；同一个面板返回 | 不让用户管理实现模块 | 清单「导航与信息架构」；既有设置入口与播放面板 | 高级项归属当前内容；全局与会话范围显式 | 进入、改变、关闭、重开保留对应范围状态 |
| 跨尺寸与输入 | Android 下贴安全区；Windows 右侧紧凑面板；内容内部滚动 | 留出视频/漫画更多可见空间 | 清单「跨尺寸与输入适配」；`MotionBottomSheet` / `MangaWindowSize` | 共享内容与控件，仅更换承载位置；支持 Esc/返回 | 窄窗口、IME、大字号无溢出，关闭路径一致 |
| 阴影、层级与材质 | 控件使用低透明玻璃层，详细数据在 PANEL，不覆盖正文 | 真实媒体背景容易破坏文字对比 | 清单「阴影、层级与材质」；`LiquidGlassSurface`、`GlassSurfaceRole.PANEL` | 复用当前玻璃，保留阅读画面与设置层空间关系 | 亮/暗/复杂画面下文本可读，不遮主操作 |
| 内容与文案 | 「目标」「正在使用」「不可用原因」分开；首层不展示推理技术词 | 设备支持与用户意图不能混同 | 清单「内容与文案」；监控系统「数值和数据状态要对得上」 | 模型名只在详情；原画回退原因就地呈现 | 错误能说明原画是否继续，以及下一步可做什么 |
| 交互手感与感知性能 | 选档立即反馈；后台写入独立于面板；不等待增强才显示原画 | 观看和翻页比参数编辑更重要 | [交互手感与感知性能](https://chatgpt.com/space/page_4742977a3c64819188a643e2c3db2735)，「先给用户合适的回应」 | 区分接到输入、可继续操作和结果确认 | 高负载选档、翻页、关闭仍可操作，旧任务不污染 |
| 数据可视化与监控 | 摘要简短；展开后按播放、超分、补帧、设备、缓存、状态对齐 | 用户要判断当前是否合适、哪个档位更稳 | [数据可视化与监控](https://chatgpt.com/space/page_b73310d9da448191a55483ec3e429305)，「按问题选表达」「数值和数据状态」 | 保留样本量/时间范围；GPU提交/完成/呈现不同名 | 缺测不同于零，试用仅说明此次内容，不推断长期稳定 |
| 任务反馈与恢复 | 下载与增强各自进度；排队/处理/校验/暂停/失败与结果一致 | 用户可以离开并找回原任务 | [任务反馈与恢复](https://chatgpt.com/space/page_1a740626a4348191b88561fcb5b37148)，「让界面状态对应真实进展」 | 已完成结果可用；重试精确失败范围，清理衍生缓存不删原文件 | 关闭重开、部分失败、取消恢复后原文件与可用结果保留 |

## 实施记录与验收边界

本轮遵循当前项目禁止本地测试、构建、编译、性能探测及 UI 自动化的交付约束。静态源码审查不等于 Android 真机、Windows 显卡或成品视觉验收。根代理集成后记录实际文件、行数与 CI 回执；以下项目必须继续明确标为设备待验收：120 Hz 手机安全区和手势、Windows 侧面板遮挡、真实模型输出、GPU计时、音画同步、seek/换源污染、长时间热降级和实际阅读锚点稳定性。

| 用户路径 | 源码落点 | 状态依据 |
| --- | --- | --- |

### 15 系统交付检查状态

配色、圆角、密度、排版、控件、动效、图标、媒体、导航、适配、材质、文案、手感、监控、恢复均已对照上表落实到源码及明确验收动作。静态确认包括：复用主题和 Ovio/Motion；没有主要蓝色下拉；没有逐数值厚卡片；漫画不显示视频 FPS 选项；目标与实际分组；缺测不同于零；提交、GPU 完成观测与最终呈现分别命名；成人记录按 content namespace 筛选；安装和设置写入由应用所有者完成。

以上为源码接线与静态审查记录。15 项的目标设备画面、连续操作与真实模型输出均未在本轮观察，不标为已通过；Android/Windows 的最终通过状态由实际运行证据填写。
